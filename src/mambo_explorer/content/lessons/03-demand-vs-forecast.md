## Beginner

Every day the balancing authority publishes a **forecast** of how much demand it
expects in each hour of the next day. Later, the **actual** demand is reported. How
close was the forecast?

**Step 1: line them up.** For each hourly UTC label, take the actual value and the
forecast value for the same balancing authority. If either one is missing or empty,
that hour cannot be compared. It is **excluded and counted**, not filled in.

**Step 2: compute the error for each matched hour.**

> **error = actual − forecast**

- **Positive** error: demand came in **above** the forecast (the forecast was too low).
- **Negative** error: demand came in **below** the forecast (the forecast was too high).

**Step 3: summarize.**
- **Mean error**: the average error *with* its sign. Positives and negatives cancel, so
  this shows whether the forecast leaned too high or too low (its bias).
- **MAE (mean absolute error)**: the average *size* of the error, ignoring sign.
- **RMSE (root mean square error)**: like MAE, but bigger misses count more.

All three are in the data's unit, **MWh**.

Two cautions:
- The forecast stored here is the latest one EIA served when the data was collected.
  It might not be exactly the forecast first published (its original **vintage**).
- This measures past accuracy for learning. It is **not** a trading test.

## Technical detail

Source definitions (Form EIA-930 instructions): "DF = day-ahead demand forecast. This
value should always be positive." Daily files contain "Yesterday's hourly day-ahead
demand forecast for today". EIA notes the forecast is generated by the balancing
authority in the normal course of business.

Calculation `forecast_error` v1, over the selection's inclusive label range:

1. For each expected hourly label, look up `D` and `DF` (latest revision) for the
   entity.
2. Exclude the label, recording why, if either value is absent, null, or
   non-numeric, or if the two units differ. If the input holds duplicate rows for a
   label, the whole result is unavailable instead of picking one.
3. For the *n* matched pairs, with eᵢ = actualᵢ − forecastᵢ:
   - mean error = Σeᵢ / n
   - MAE = Σ|eᵢ| / n
   - RMSE = √(Σeᵢ² / n)
4. If n = 0, the result is **unavailable**.

The result keeps:
- the pair count and every exclusion with its reason
- per-pair errors
- the hours over- and under-forecast
- the largest absolute error and its label
- the revision and run reference for both sides of every pair

It does not retain earlier forecast versions. The store keeps every revision it has
collected, but revisions made before the first collection are not recoverable here.
